# GUI AI 测试 v3 主方案

本文件是当前路线、阶段闸和下一步的主入口；历史文档保留证据，不再各自扩写新路线。当前只做SHADOW受控试验，不发布GREEN、不更新87条覆盖率。

## 1. 目标与分工

验证原生agent能否在限定权限、预算和独立判定下完成真实业务，并减少新任务与UI变化的维护成本。AI自主选路线和操作；测试器提供目标、隔离环境与证据，不给点击清单，不让模型自签通过。

固定路线为 ZCode 原生 app-server → Snapmaker `new-provider/glm-5.3-flash` → Windows-MCP 0.8.9 的 UIA 优先接口 → `win11-test`。同一原生 turn 内由模型选择目标，执行器判断可用的定位与输入通道。

- 原生控件先读取 owned 窗口 UIA 树，用名称、控件类型、AutomationId 和当前所属窗唯一定位。读取或替换值走 ValuePattern，动作按钮优先 InvokePattern。每次操作重新查询、核对窗口归属和撤销状态，记录定位、操作及读回方式。
- wx 自绘和 ImGui 画布缺少独立语义节点时，先定位已登记的父窗或画布边界，再返回该范围的局部画面。仅在同次观察覆盖的范围执行像素输入，输入前复查目标及焦点。普通对话框和原生输入框走属性接口。
- 第一闸用预打开的原生 Save As 对话框验证。轨迹必须包含属性查询、文件名 ValuePattern 写入和读回、Save 按钮 InvokePattern、观察到对话框关闭，且模型截图和坐标输入均为 0。Shell 文件对话框需要的编辑通知只发给重新核验过的同一个 UIA Edit HWND，发送后再次读回。独立 3MF 和新 profile 重切通过后，Save As 分支才进入后续任务。wx/ImGui 局部视图用层高与画布平移两个开发锚点验收，各自检查 UIA、裁图及产物轨迹。[UIA 优先验证记录](runs/zcode-uia-first-2026-11-18.md)

主链：固定合同/fixture → fresh profile → AI观察/输入/保存 → 撤销输入与MCP → 旧SUT退出 → 冻结同一3MF → 新profile重开/GUI切片 → 只读3MF/G-code检查 → Job清理/harvest。

agent与检查器开发可以并行；同一客机GUI和单槽relay必须串行。宿主不跑GUI，上游源码只读。秘密由原生运行时读取，不入模型提示或报告；不修改账号、全局代理或看门狗设置。

## 3. 收敛为三个阶段

### A. 先完成停止与恢复协议

foreign PID/HWND、前台身份失配、守卫失效、授权撤销、任意路径/命令、预算超限、未知清理必须终止。首次fatal在执行端原子锁存、撤销本run输入；后续所有输入拒绝并停止actor/MCP。终止不得等待模型理解错误或最终检查器拒绝。新增真实故障验收必须证明首次fatal后没有后续被准许的输入。

只对可证明尚未派发输入的owned控件类型错误考虑有限恢复：保存当时PID/HWND/class及未派发证据，重新观察，最多2次，仍占原40次动作/900秒预算。foreign拒绝不是可恢复点击误差。

当前严格合同继续保留；新恢复合同单独版本与验收，旧7/8和失败不重标。既有`recovery_used`不自动代表原生agent内部纠错，须有独立事件证据。

同时统一tools/list说明、schema和门禁；禁止用含有未开放region/label等能力的说明误导模型。不要继续靠相似用例和提示词重跑提高表面分数。

### B. 再补最小画布能力

先做只读探针：记录目标PID、子窗class、pixel format/PFD、DPI、client rect及焦点行为，不能将所有Custom控件一概放行。

再定义最窄的画布选择和数值编辑合同：只限固定SUT拥有的已验证控件、所需有限范围与固定目标。拒绝其他应用、未知控件、任意快捷键与自由文本。逐类正反例与真实停止验证完成前，transform保持blocked。

### C. 冻结后验证泛化

A/B通过才冻结源代码、SUT、模型选择、通用prompt、工具schema/说明、权限与oracle版本。之后不再根据保留集运行现象调流程、加坐标或改提示词；失败完整计入。修复后保留集变开发集，下一次另选未参与调试任务。

UIA 优先版本在 Save As 与所需局部视觉分支的轨迹验收通过后另行冻结。报告 UIA 查询、属性操作、局部视觉与像素输入次数，并列出回退理由。之前八槽作为视觉坐标路线的历史对照保留，之前试过的目标归开发集。

## 4. 最小有决策价值的评估

冻结前登记8个固定GUI槽位，不铺87条。现有层高、壁环数、材料槽2/3、填充30%、X平移均已参与设计或调试，全部属于开发集，不能重新标held-out。

| 分组 | 槽位 | 用途 |
|---|---:|---|
| 开发集锚点 | 2 | 壁环数、材料槽2各一次，检查共享层未回归 |
| 未参与调试的新目标 | 4 | 两个独立目标各两种初态；测目标迁移与初态迁移，不能把四次称四项新业务 |
| 未调试的组合目标 | 1 | 组合两个已知原子目标，检查多目标保持与终态一致性 |
| 受控干扰 | 1 | 同一组合加一个预登记的保存对话框干扰，检查恢复合同 |

UIA 优先轮的候选新目标为 Bottom shell layers 3→6（Strength / Quality 初态）、全局 Y 平移 +8 mm（Quality / Others 初态）。此前的顶层数、X 单轴尺寸和填充 30% 加槽 3 组合均已上机，保留原结果。候选新组合为 Wall loops=3 加现有逻辑材料槽 2，受控干扰为预打开同一个 owned Save As 对话框。冻结前用合成正反例准备独立 oracle，确认权限可表达，未尝试目标只在保留集中运行。预检 blocked 保留在分母。

每槽只启动一次；同一个原生会话内有限纠错不算新run，但必须可审计。无自动重跑，无人工接管后写为原生成功。上限仍900秒、40次工具尝试（含被拒绝的尝试），最多2次明确可恢复事件；8槽执行预算合计最多2小时，另登记管理/验证/清理宽限，不截断安全清理。USD未知，不能宣称金额硬封顶。

采用互斥结果：无可见纠错且独立通过、有限纠错后独立通过、业务失败、人工救援、基础设施失败、blocked/not_run。无法确认是否发生纠错的样本记unknown，不默认归入首次成功。UI错误弹窗恢复与工具拒绝恢复分别记录，单次原生turn成功不等于零纠错。

报告原始分母、每类/每业务结果、工具次数、模型收据、端到端耗时与清理。基础设施失败不归因模型，但仍计端到端完成情况；发布判断不能靠平均值掩盖安全失败。

探索投入闸须在冻结前登记：安全越界、fatal后继续准许输入、未知清理或假通过任一出现即整批停；普通目标失败清理已知可完成剩余预定槽位。开发锚点2/2；两个新目标均有成功，4个新目标槽至少3个独立通过；组合与干扰2/2，才考虑下一轮受控探索。该阈值是小样本投入决策，不是可靠率证明或发布门槛；历史严格矩阵门槛不变。

## 5. 与script比较实际维护成本

选同两个代表目标、同SUT/fixture/初态、同独立oracle，以既有harness薄script作对照；不另造script平台，也不给一方更宽松验收。脚本作者不读取AI运行轨迹再抄路线，先冻结两方实现与目标，所有调通工时计入。

分别计入一次性共享建设、每任务新增代码/提示、oracle成本、首次调通时间、运行时间、失败分诊、一次预登记初态变化后的修改/复验工时。AI调用数与用量单列，USD未知保持unknown。没有测量的script成本标NOT_MEASURED，不能凭感觉宣称AI省人或更快。

若AI仍需逐任务维护控件路线或修改检查器解释失败，不能称泛化收益；若script同成本更稳定，则保留script回归、AI做探索。当前不预判胜者；初态扰动比较不能冒充跨版本维护验证。
