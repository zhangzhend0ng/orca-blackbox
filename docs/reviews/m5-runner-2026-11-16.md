## 条件、动作与 tier

- Error Handling (C)：菜单返回 `(None, None)` 或无 OCR 时显式失败／有限重试；异常清理不吞原始异常；通过真实函数体的替身单测。保持原阈值，不声明菜单失败根因已解决。
- Fix Verification (C)：旧 HEAD 在同组 20 项 m5 单测中 13 failed / 7 passed，修复后 20 passed；客机 m5a 已通过公共 boot/delete/add 路径，后续预设切换 RED；其他 m5 未复跑，状态如实保留。
- Input Validation (N) / Code Review (C)：同步是否成功按 guest 端 Git 退出码及明确 SYNC_OK 状态，不能扫描整段 Git 日志关键词。已记录旧 gate 将提交标题 `errors` 判失败的现场；新 gate 在真实同步中接受相同提交历史并继续启动 suite。dirty 检出仍拒绝；未使用 NoSync 绕过。
- pytest Patterns (C)：无 GUI 单测使用实际生产函数 AST 与替身依赖，不关闭 GUI rig fixture；副作用由 fixture 隔离。
- Scope Control (A)：保留原宿主和客机未提交改动，验证使用独立客机检出。
