## 审阅发现及闭合

- (C) 原同步 verifier.start 可在读取/扫描 BMP 时阻塞取消：改为只读 worker + poll，分块协作取消，cleanup 需确认线程结束。
- (C) 非 daemon 只读 worker 若卡在 OS 读会拖住 CLI：改为 daemon；不据此伪报 cleanup 成功，未确认仍隔离。
- (C) Windows Python stdout 编码与严格 UTF-8 verifier 不一致：adapter 固定 PYTHONIOENCODING=utf-8，覆盖外部值。
- (C) 新运行可能与 legacy suite 共享桌面：V3 在分辨率调整和任务重注册前检查既有 suite/app 占用，发现即拒绝。
- (C) fresh profile 分支可能全局 taskkill：固定 adapter 用不存在的独占 profile 且不传 fresh；run-owned m0 机械拒绝复用与 fresh。

## Win32 接口复核

guest 默认解释器为 Python 3.11。已核对 [CPython 3.11 的 _winapi.c](https://raw.githubusercontent.com/python/cpython/3.11/Modules/_winapi.c)：CreateProcess 内部构造 STARTUPINFOEXW，读取标准句柄与 lpAttributeList，并自动加入 EXTENDED_STARTUPINFO_PRESENT 和 CREATE_UNICODE_ENVIRONMENT；当前调用的 flags 和返回四元组解包匹配，无需手工重复构造 STARTUPINFOEX。

已核对 Microsoft 的 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 与 [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)：kill-on-close 依赖最后 Job handle 关闭，nested job 约束可能让分配失败。因此当前 Job 不继承、不 breakaway、分配失败即收尾隔离的处理合理；实际计划任务继承环境仍需客机实测。

## 剩余边界

Python 只读线程取消是协作式，不能强制抢占 OS 文件 I/O；超时保持隔离。Job 后代归属依赖 Windows 正常继承，安装器/服务等外部代启动不在本批自动支持范围。hv_harvest -V3 拉取独立汇总，run-owned 原始截图与证据仍在客机，详细复核须读取对应 run。V3 预检不能控制用户在检查后手工启动其他旧流程，试点仍需独占客机操作窗口。

没有新增模型接入、切片回归或发布晋级；这些不是本批完成项。
