## m3 混色族 RED 根因：SUT 构建差异（非驱动层问题）

- m3 混色族（BLACKBOX_CASES「混色匹配 MixedFilamentBatchDialog，2026-08-29 批次」）面向的 UI 锚点：
  `"Color Mixing Match"` 标题条 + 原生 `#32770` 批量对话框 + `MixedFilamentBatchDialog.cpp:2290` 喷嘴警告（混色_util 头注释：08-24 dev build 实测）。
- 本机 SUT 源树（只读核查）**完全没有**这些符号：`grep -r "MixedFilamentBatchDialog|start_batch_match|not supported for the current nozzle" src` 零命中；
  其混色入口是 `Sidebar::init_color_mix_panel`（Plater.cpp:5803 起，标题 Label 为 **"Color Mixing"** 的 StaticBox + `m_btn_add_color_mix`），与探针子控件枚举/OCR 完全吻合。
- 即：junction 指向的 nightly-builds @ c98c6d3（2.3.5，07-08 构建）**早于/不同于** m3 用例所校准的 dev build。m0–m2 全绿证明驱动层（消息注入/模板/GL 截图/切片链）在本机健康，m3j–m3l 的 RED 属预期的版本差异，如实在本口径记录，不冒充任何一方的回归结论。

## 环境差异清单（vs win11-test 口径）

1. **GameViewer 虚拟显示适配器常驻**：env_check 每例提示 SendInput 路线被抑制；用例走消息级注入不受影响（m1 实测绿）。
2. **物理机联网**：每次启动弹 "new version of snapmaker orca" 更新窗，launcher 统一 WM_CLOSE dismiss（PITFALLS §19 同类现象）。
3. **SUT 构建分支不同**（m3 RED 根因，见上节）。
4. **system presets 种子来源**：repo 无 `resources/profiles` → 兜底 exe-side `resources/profiles`（junction 解析打印为 `C:\orca-main\OrcaSlicer\build\src\Release\resources\profiles`；datadir/system 实收 vendors = OrcaFilamentLibrary + Snapmaker）。
5. 任务预想的 Mesa/字体缺失**未出现**：GL viewport 渲染正常（彩色占比断言全通），Tesseract 5.4.0 可用。
