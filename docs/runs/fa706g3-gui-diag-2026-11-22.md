## #268 填充图案弹窗（Sparse infill pattern）

现场：Strength 页 → Infill 组 → `Sparse infill pattern` 行（client y≈980）。值区点击
（canvas_left−90, 行 y；本机 canvas 左缘 x=426 → 点击 (336,987)）打开弹窗：
`wxWindowNR` title='panel'，rect [246,440,457,967]（211×527px），**零子窗口**
（`268_00b_popup_census`；与 VM 2.4.0 run 6ec6f4c0 的 "children: []" 一致：纯自绘列表）。

列表顺序（自绘枚举序，非纯字母序）：Rectilinear, Aligned Rectilinear, Zig Zag,
Cross Zag, Locked Zag, Line, Grid, Triangles, Tri-hexagon, Cubic, Adaptive Cubic,
Quarter Cubic, Support Cubic, Lightning, Honeycomb, 3D Honeycomb, Lateral Honeycomb,
Lateral Lattice, Cross Hatch, TPMS-FK, **Gyroid（第 21 项）**, Concentric, Hilbert Curve,
Archimedean Chords, Octagram Spiral, …。可见页约 16.5 行；**Gyroid 恰好是折叠线下
第一个完整行**（Honeycomb 之后仅露约 8px 顶缘，低倍 OCR 误读为 "GR on"）。

### 六机制逐一实证（每项：列表动否 / 停在哪 / Gyroid 可见否 / 弹窗存活否）

| 机制 | 实证结果（截图） |
|---|---|
| (a) typeahead：弹窗置前景后真实单按 `g` | **无效**。列表纹丝不动，弹窗存活（`268_a1`） |
| (a2) typeahead 连打 `gyroid`（KEYEVENTF_UNICODE） | **无效**。同上（`268_a2`） |
| (b) 拖动弹窗"滚动条"（右缘 x=r−6） | **触摸式语义，非原生滚动条**：起点落轨道=先翻一页；向下拖→列表回到顶部；**向上拖→内容跟手上移、深层项入镜**（Gyroid 可见，`268_b/b2/b3`）。可用但方向反直觉 |
| (c) 小步滚轮：1 格 + ≥400ms 沉降 | **有效（本机制解）**。1 格→顶部变 Locked Zag；**2 格→Gyroid 完整入镜**（TPMS-FK 与 Concentric 之间）；第 3 格仍动（Quarter Cubic 顶）；**第 4–6 格冻结**（`268_c_wheel1x_step1/3/6`） |
| (d) VK_DOWN 真实键 | **1 次即关闭弹窗** |
| (d2) VK_DOWN PostMessage（WM_KEYDOWN/UP） | 同样 **1 次即关闭弹窗**（PM 单发验证） |
| (e) Home/End（VK_END PostMessage） | **被忽略**：弹窗存活、列表不动（已在顶部，HOME 无增量信息未单测） |
| (f) 光标移到列表下半（80% 高度）再滚 1–2 格 | **有效**，与 (c) 同：首格滚动、累计约 3 格后冻结；Gyroid 保持可见（`268_f`） |

### 可复现选中配方（实测走通）

1. 点击值区 (canvas_left−90, 行 y) 打开弹窗；
2. 真实滚轮 **−1 格 ×2，每格间隔 ≥400ms**（光标在弹窗中部或下半均可）；
3. OCR 确认 Gyroid 入镜（容错：`gyroid` 小写包含即可）；
4. 点击 Gyroid 词框中心 → 弹窗关闭即提交；
5. 等 2.5s 重建，值区（x≈240–426、行 y±15，放大 4×、暗字带检测）OCR 读出
   **"Gyroid"**（`268_g_value_zone_gyroid`；该行值区低倍 OCR 常空——需放大+暗带定位）。

附加机制（引擎可复用）：
- **提交后重开弹窗，列表自动滚到选中项**（Gyroid 居中高亮，`268_h_reopen_after_commit`）——
  "commit 后 reopen" 可作为校验/二次操作锚点。
- ESC（PostMessage 与真实键）**都不**关弹窗；**再点一次 combo 值区 = toggle 关闭**（无变更）。

### 与 VM 2.4.0 记录的差异（版本标注）

- VM：真实光标轮与 PostMessage 轮均不累积、可见页恒从 Aligned 起。本机 2.3.5：真实
  单格轮**累积 2–3 格有效后冻结**，未见弹窗内"回弹到顶"。（弹窗内未测 PM 轮。）
- VM：VK_NEXT 关弹窗、WM_CHAR 无渲染（一致复现 typeahead 无效）。2.3.5 额外发现
  **VK_DOWN（真实与 PM）也关弹窗**——版本间键盘处理有差异的可能，供 2.4.0 复核。

## #259 熨烫 Speed 行（ironing speed）

现场链条（2.3.5）：

1. 种子配置默认**简单模式**：侧栏页签无 Speed，Ironing 组不可达。点 Process 行
   Advanced 开关（本机 (330,611) 一带）切**高级模式**后：页签行变
   Quality/Strength/**Speed**/Support/Multimaterial/Others。
2. Quality 页小步轮滚到 **Ironing 组** → `Ironing type` 行（y≈880，值 "No ironing"）
   开弹窗 [246,905,427,1017]，4 项：No ironing / All top surfaces /
   **Topmost surface only** / All solid layers（`259_00`）。
3. 点 "Topmost surface only" → 弹窗关、页面重建。**重建后 Ironing 组新增**：
   Ironing type（值区**截断绘制**为 "~ Topmost sur…"，`259_01b`）、Ironing Pattern、
   Ironing flow 10%、Ironing line spacing 0.15mm、Ironing inset 0mm、Ironing angle −1
   （`259_01c` 高倍标签取证）。**Quality 页上没有 Speed 行。**
4. `ironing_speed` 真身在 **Speed 页签**：源码双证——`PrintConfig.cpp:3618`
   label=**"Ironing speed"**、sidetext "mm/s"、default 20、comAdvanced；
   `Tab.cpp:2433` 挂到 Speed 页 `speed_settings_other_layers_speed` 组。现场 Speed 页
   该组（Gap infill 50 与 Overhang speed 区之间）像素级放大 OCR：绘制文案精确为
   **"Ironing speed  30 mm/s"**（本预设值 30；`259_02` 8× 放大、`259_03` 上下文）。
5. **VM #259 OCR 未命中的三层根因**：(i) 行不在 Quality 重建页、在 Speed 页签；
   (ii) 前置条件 = Advanced 高级模式（种子默认关，且 VM 侧流程未记录此开关）；
   (iii) tesseract 把词首 "I" 读成 "l"（'lroning speed'）——匹配需 'roning speed'
   或大小写模糊；另外 combo 值区会截断绘制（"Topmost sur…"）。

## 侧栏视口滚动病理（两案共用，引擎注意事项）

- **间歇死锁**：弹窗交互（开/提交/toggle）之后真实滚轮常对侧栏失效；简单模式下更长
  时间失效。**面板整体重建（Advanced off→on、页签切换后首段）可复活**。复活配方：
  Advanced 双击切换 → 点目标页签 → 立刻 1 格×N（N≤10）小步轮 + 每格 OCR 校验。
- 大格（≥2 格/次）会**复位到顶**（同 VM 弹窗"回顶"描述的姊妹行为）。
- 右缘 x≈405–419 **悬停才绘制**覆盖式滚动条（hover 前后像素差分定位）。
- 系统级干扰：一次 "Windows 安全中心警报" 弹窗抢占前台造成全局输入失效段——
  跑批 sweep 应把系统安全弹窗纳入 BLOCKER_TITLES（现仅 update/wizard）。
