# UIA 执行层修正与试跑 2026-11-18

本轮为开发复验。历史 UIA 优先矩阵保留 1/8。冻结的 Y 两槽最后一份模型响应均请求两次 `Screenshot`。原生日志能确认两次只读观察近同时启动。ZCode 会先发出整批 `scheduled` 事件，再启动工具。旧驱动以第二个排程事件为停机依据，未按实际启动顺序判断。没有观测到并发输入。

- 仅隔离的 ZCode app-server 进程启用 `ZCODE_MAX_TOOL_CONCURRENCY=1`。宿主校验单调用执行组及真实启动、完成和可信收据的顺序。桥在明确的致命拒绝后停止转发。客机仍检查实时窗口、布局和控件归属。
- wx 侧栏和 ImGui 画布用 `region_name` 请求，由执行器重算当前边界并回传裁图坐标。无法省去的像素点击仍须落在最新裁图，提交前重新核验目标。失效裁图或误以坐标命中可读 UIA 的 owned 控件时，可以有限次拒绝并要求刷新，输入保持未派发。未登记的同所有者弹窗仅可结构化观察。
- 复验优先覆盖旧 Y 平移、壁环数、逻辑槽 2 三个失败目标。另在固定 Quality 初态对比层高与 X 平移两条业务的 ZCode 和脚本路径。两者共用同一冻结 SUT、fixture、保存后独立重开切片和业务检查。时长使用客机端 setup 完成到停输的相同边界，脚本额外记录编辑与保存的纯动作时长。保留每槽真实结果和清理收据。[脚本对照口径](../V3_SCRIPT_COMPARISON.md)
