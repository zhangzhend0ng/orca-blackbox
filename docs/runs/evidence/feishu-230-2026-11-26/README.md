# 飞书 #230 导入工程：在 2.4.0 上预期不成立（RED）

记录 `reczz28aa4fiY8fE`（P0）要求通过「文件→导入」导入一个由本软件导出的 `project.3mf`（含 2 个盘、每盘不同对象与工艺配置），预期「盘数与对象完整还原，各对象工艺/耗材配置与导出前一致，无丢失」。

**结论：Snapmaker Orca 2.4.0 的「文件→导入」只加载几何。两轮客机实跑（不同提交）结论逐项相同：盘数从 2 变 1，两个对象都进了「未分配」区并被重新摆放，盘级和工程级配置没有带过来；只有「无丢失」成立。** 这是产品行为与飞书预期的差异，判据没有放宽。飞书状态保持空白。

用例分两个会话。第一个打开 #242 的两盘保存件（盘 `Keep` 上是 Alpha，盘 `Remove` 上是 Bravo，挤出机分别是 1 和 3），另存为本轮的 [project.3mf](48e3aa7d-run1-project.3mf)，作为「由本软件导出」的输入。第二个从空盘的 U1 模板工程开始，File→Import→`Import 3MF/STL/STEP/SVG/OBJ/AMF...` 选中它，再另存为 [imported.3mf](48e3aa7d-run1-imported.3mf)，逐项比较。

| 飞书预期 | 读数 | 结论 |
| --- | --- | --- |
| 盘数与对象完整还原 | 盘名 `Keep`、`Remove` → 只剩 1 个盘 `1`；Alpha、Bravo → 都在未分配区；两件的世界坐标三角面都变了（被重新居中） | FAIL（4 个子项都不过） |
| 各对象工艺/耗材配置与导出前一致 | 对象级只比了挤出机（1 / 3，保留）；两个盘的设置都不存在了；工程级配置有 86 个键不同，就是导入前模板工程的配置 | FAIL（盘级、工程级；对象级因只有挤出机可比而通过） |
| 无丢失 | Alpha、Bravo 都在，网格与导出前相同，名字没变 | PASS |

读数在两份 [analysis.json](48e3aa7d-run1-analysis.json) 的 `restore` 里。判据里有一道防假绿的核对：导入前的模板工程与导出件本身就有 86 个键不同，所以「导入后等于导出前」不可能是没改动造成的。

用例作者按 tag `sm-v2.4.0` 读源码，与此一致：菜单项调用 `Plater::add_model()`（`MainFrame.cpp:2609`），它以 `LoadStrategy::LoadModel` 进入 `load_files`（`Plater.cpp:18054`）；读出的盘数据随即释放、`load_from_3mf_structure` 被注释掉（`Plater.cpp:14243`）；对象与部件的配置被重置，只恢复挤出机（`Plater.cpp:11863`）；工程级配置只在带 `LoadConfig` 时应用（`Plater.cpp:11997`）。

**给测试同事的两点。** 一是这条预期的行为对应的是「文件→打开项目」（飞书 #200「工程及盘布局正确恢复」，已自动化），「文件→导入」在 2.4.0 上不还原盘和配置，这一行需要定口径：改步骤为「打开项目」，或保留为产品差异。二是夹具的限度：两盘的盘级设置相同、两个对象没有各自的工艺覆盖，「每盘不同工艺配置」没有被这份夹具覆盖。
