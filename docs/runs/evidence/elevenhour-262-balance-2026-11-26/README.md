# 飞书 #262「对象整体流量不变」的口径核算

**结论：「对象流量倍率 = 1 被如实写入」成立；「累计正挤出逐毫米不变」不成立。** 顶面 +10%、底面 −10% 之后，对象累计正挤出的变化恰好是 `0.1 ×（基线顶面 − 基线底面）`；3DBenchy 的顶面基线挤出约是底面的 5–6 倍，所以差值是 +8.65 ~ +10.63 mm（+0.228% ~ +0.281%）。四组已有数据（两台机器、两种执行方式、含一组反向对照）都落在公式的一个写入步长内，这一项不需要再实跑。

本目录只做离线重算，输入都是仓库里已有的收割件，没有新的 GUI 运行。工具是 `tools/check_surface_flow_balance.py`（统计口径：对象标记内、带 XY 且 E > 0 的移动，按 `;TYPE:` 分特征）。

单位 mm（E 的累计长度）。四组里：

- 顶面、底面各自的路径段数不变，每段 E 与「倍率 × 基线」之差不超过一个写入步长（1e-5）。
- 其余 8–9 类特征的路径与挤出逐段相同（segment streams identical）。
- `print_flow_ratio` 在保存的配置里 1 → 1。
- 反向对照给出反号、同量（−10.63）的变化，说明差值来自顶、底两处倍率，而不是别处漏写。
- 工具的五项检查里 `object_positive_unchanged` 为 FAIL 是预期的：它正是在检验「累计正挤出不变」这一读法。

读法与建议：飞书预期第三条「对象整体流量不变」若指 `print_flow_ratio` 保持 1，则成立；若指累计挤出总量不变，则与第一、二条在算术上不能同时成立（除非顶、底基线挤出相等）。建议测试同事把它改写成「对象流量系数保持 1」。这里度量的是 G-code 指令，没有称量实物。
