# 飞书 #254 层高组合：G-code 两段一致，客机上红在护栏中断后的预览

记录 `reczz28b6mRB1GVG`（P0）要求固定 U1 0.4 mm、PLA、0.20 mm 标准工艺，添加标准球，先按默认参数做基准切片，再应用 `layer_height = 0.20`、`initial_layer_print_height = 0.25` 重新切片，对照基准检查配置、预览和 G-code。预期「组合参数写入正确，切片成功并产出 G-code；首层 Z = 0.25 mm，第 2 层起按 0.20 mm 递增；层数、总高度和后续层 Z 步进与默认基准一致」。

**结论：预期里的三句在 G-code 上都成立，用例在 fa706g3 上整条通过；在客机 win11-test 上总判仍是 FAIL，红在第 4 步的预览对照。** 客机只有 4 GB 内存，切球体时运行期内存护栏必然弹出；应答继续之后切片完整、G-code 与基准逐行相同，但预览里的球体只显示成一层半透明的残影，和基准预览的重叠只有 68%。fa706g3 没有弹护栏，两张预览完全相同。所以这一条不进默认回归，飞书状态保持待实现。

**G-code 这一边三轮客机读数相同。** 点 Slice 后 `Export G-code` 行在 5.0 秒内启用（目标段 7.4 秒，中间应答了护栏）；两份 G-code 各 100 层，首层 Z 0.25 mm、末层 20.05 mm、层间步进 0.2 mm；[基准](3f55a59a-run1-baseline.gcode)与[目标](3f55a59a-run1-target.gcode)的可执行行 23,933 行逐行相同，配置块 570 个键里只有 `filament_ids` 不同（身份键）。fa706g3 的两份 G-code 同样逐行相同。

探针二先验证过「截图拍早了」这个假设：用例改成等画面连续三帧不变再拍（[66d8233e 的 analysis](66d8233e-run1-analysis.json) 里 `settled` 记了 3 帧、1.8 秒），残影稳定不动，重叠没有变。所以残影不是时机问题。客机空闲时可用内存只有 1.1 GB（共 4.0 GB），切球体时护栏必弹；fa706g3 内存充裕，不弹。护栏中断并继续之后预览不恢复正常，这一点与三轮客机读数一致，和 fa 的对照一致；客机不弹护栏时会怎样，本轮没有条件直接观察——上一轮那次完整通过（262.972 秒）是护栏没有弹出的一轮。

**给测试同事。** 两条可以跟进。其一（产品）：切片被 `Memory Usage Warning` 暂停、点 `Yes, Continue` 完成之后，预览里的模型只显示成半透明残影，需要重新切或切页才恢复——本轮没有验证怎样恢复。其二（环境）：win11-test 的 4 GB 内存让每个切球体的用例都会撞上护栏；把虚拟机内存下限提到 8 GB 左右可以避免，是否调整由你决定。
