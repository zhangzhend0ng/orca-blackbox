## 九小时节奏

| 相对时间 | 三机同时推进的工作 |
|---|---|
| 0–0.5 小时 | 三机并发预检、派首单，记录飞书编号、记录 ID、原步骤、预期、夹具和 run ID；可开跑的机器立即启动基线。 |
| 0.5–3 小时 | 各机交一份分段计时与业务证据，选最大的可控耗时做单变量候选。VM 优先看 #276 提交回读，Windows 实体机看 #264 长页与多编辑框，Mac 看壁环副本保存及重开。复算 agent 同步准备错值或夹带无关改动的反例。 |
| 3–6 小时 | 在原机同构建同初态跑一遍基线、至少两遍候选，换初态单列。空闲机从飞书标为已自动化的 92 条中挑已有部分证据且与平台匹配的下一条。优先补齐同一条原用例里的连续动作和预期，例如编辑→保存→独立重开→切片。 |
| 6–8 小时 | 需要正式评级的 Windows 实体机候选交客机复核，Mac 按本机构建单列。为原生 GLM‑5.4 与脚本共用判据的配对留出同机窗口。参考[上轮运行](glm54-maintenance-265-276.md)，已按 #265→#276 做过首次与换初态对照；如重新执行两条正式配对，保持此顺序。 |
| 8–9 小时 | 停派预计不能在窗口内收割的新单，各机收割、清理，总控交叉审查、执行受影响验证和必要回归。把已验证改动合入并推送 `software_testing`，用 `git ls-remote` 核对远端 SHA。交付全表和收据，未完成项附具体失败点、恢复入口。 |
